# Vibe-coding 指南 — 政策实验室（PolicyLab）

> 本系统如何用 AI 编码工具构建、其背后的设计思考，以及一份可粘贴进 AI 编码助手、用于复现（或改编）到你自己课堂的完整提示词。

---

## 1. 这里的「vibe-coding」是什么意思

你不是从规定函数与类开始，而是从 **vibe**——你想要的感受与学习目标——开始，让 AI 起草架构、代码与文档，你再用 **硬性约束** 去驾驭、用 **验证** 去把关。对教育工具而言，最要紧的两件事是：

1. **不可违反的约束**（例如「必须是静态站点」「选择 → 结局必须确定性」）。
2. **可运行的验证**，使 AI 生成的内容不会悄悄破坏体验。

本仓库正是这样构建的：以简短的迭代回合推进，每个回合都用 `node` 跑一遍语法与逻辑自检。

## 2. 设计思考

项目沿用 Stanford d.school 设计思考模型——共情、定义、构思、原型、测试——应用于一个问题：学生不 *感受* 得到一项政策为何「知易行难」，因为被叮嘱「别那么做」是会被忘记的。

| 阶段 | 本项目的轨迹 |
|---|---|
| **1. 共情** | 目标课程 PUA6027 把两条线索并置：科技与创新（科研如何转化为产品、产业如何被重塑、伦理法律红线在哪里），以及政策过程（政策如何分类、如何在宏观／中观／微观层面递归、为何「知易行难」）。分开讲授会产生两种熟悉失败：学生写一份产业规划，把合规当一页没人读的幻灯片，或得出结论「政策」就是「别做」。都不是课程想要的。观察：互动、近似游戏的经验比讲座警告留存更久；让学习者 *看见* 后果（数字移动）使教训扎根。 |
| **2. 定义** | 核心痛点：学生无法体会「好政策 ≠ 好结果」。设计目标：把 Matland（1995）模糊—冲突模型，从一个抽象二维表，变成学生亲手撞上的「政策打折」机制。 |
| **3. 构思** | 参照《一念之差（Choices）》的「情境驱动」骨架——随机抽场景、分步决策、多种结局——但把落点换成本课程的 Matland 四象限；每局固定一个政策层面，呼应混合政策周期理论。 |
| **4. 原型** | 先做一个垂直切片：3 个通用政策难题、每局 3 个决策点、纯前端无构建。引擎与数据分离，加场景只加 JSON。 |
| **5. 测试** | 每个迭代回合用 `node` 模拟一局完整游玩，校验 Matland 落点、指标简报与 Word 导出字节合法。 |

| 迭代回合 | 这一轮做了什么 |
|---|---|
| 0. 立项 | 决定新建独立仓库 `PolicyLab`（而非 fork / 分支 Choices），复用 Choices 的「静态托管 + 中国可访问」纪律，但重写引擎为「情境驱动的状态模拟」 |
| 1. 引擎 | 写 `js/engine.js`：指标表（11 项）、Matland 模糊—冲突二维、层面基线、确定性结算、期末档位 |
| 2. 数据 | 写 `data/scenarios.js`：3 个通用政策难题场景，每步带模糊／冲突增量与意图效果 |
| 3. 仪表盘 | 写 `js/dashboard.js`：零依赖指标简报渲染 |
| 4. 控制器 | 写 `js/app.js`：随机开局 → 分步决策 → 每步「后果说明」→ 四象限结局 → 详细复盘 → 导出 |
| 5. 风格 | 改为严肃政府／公共行政风（浅灰底、深海军蓝、宋体标题），去掉 Choices 的游戏黑底 |
| 6. 后果与复盘 | 加每步「后果说明」面板与结尾详细复盘（决策轨迹 + 指标总账 + Matland 归因），贴近 Choices 的反馈—复盘节奏 |
| 7. Word 导出 | 写 `js/docx.js`：零依赖手写 ZIP + OOXML 生成 .docx，离线可用、中国可访问 |
| 8. 文档 | README + 教学指引 + 本 Vibe-coding 指南 + 示例复盘报告，统一为 EdTech「家规」结构 |

## 3. 完整提示词（可复现 / 改编）

下面这份提示词，可粘贴进任意 AI 编码助手，复现一个类似的政策模拟器，或改编到你的课程：

> 我要构建一个面向研究生课程的政策模拟 Web 应用，纯前端、无构建、无后端、可离线、可部署到 GitHub Pages 且中国可访问。请按以下约束生成代码：
>
> 1. **情境驱动结构**：开局随机抽一个「政策难题场景 × 政策层面（宏观／中观／微观）」组合，每局固定一个层面；玩家依次面对 3–4 个决策点，每个决策点选一种「推行方式」。
> 2. **核心机制**：每条选项携带「模糊度增量」与「冲突度增量」，叠加本局层面的基线，得到本步模糊度／冲突度；一局结束后取均值，依 Matland（1995）模糊—冲突模型落到四象限之一（行政性／政治性／试验性／象征性执行），并给出叙事解释。
> 3. **每步即时反馈**：每选一步，立即说明这一决策改变了哪些指标、把模糊／冲突推向何处、当前整体执行性格为何。
> 4. **结尾详细复盘**：决策轨迹 + 社会发展指标总账（开局 → 终局、由哪些步推动）+ Matland 归因。
> 5. **导出**：可导出 Markdown / JSON / Word（.docx），其中 .docx 必须零依赖（手写 ZIP + OOXML），不可调用任何第三方库或网络。
> 6. **风格**：严肃的政府／公共行政风（浅灰底、深海军蓝主色、衬线标题），不要游戏黑底。
> 7. **引擎与数据分离**：场景写在独立 JSON/JS 数据包，加新课程只需追加包，不改引擎。
> 8. **确定性**：核心逻辑禁止随机数（仅抽场景／层面可用随机）。
>
> 请给出 `index.html`、`css/style.css`、`js/engine.js`、`js/app.js`、`data/scenarios.js` 的完整代码，并在 `data/scenarios.js` 顶部注释字段含义。

（把第 2 节「设计思考」与这份提示词结合，即可让 AI 从同一套 vibe 出发，产出贴合你课程的另一套模拟器。）
