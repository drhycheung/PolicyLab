# 政策实验室 · PolicyLab

一门贯穿全课程的政策模拟系统——学生以政策委员会身份逐期制定政策，由确定性引擎将「政策意图」推演为「执行结果」，并跨学期持续追踪社会发展指标。

**▶ 在线试玩：<https://drhycheung.github.io/PolicyLab/>**（启用 GitHub Pages 后生效）

---

**课程归属：** PUA6027 科技、创新与政策（香港教育大学）。亦可作为其他科技政策类课程的政策模拟练习。课堂组织方式见教学指引。

学生接手一个模拟经济体的政策委员会，按课程进度逐期制定政策。系统依据政策的「模糊度 × 冲突度」推演出执行结果，并持续追踪十一項社会发展指标。课程结束时，小组导出政策档案，作为案例比较与反思的原始素材。全程纯前端、无构建、无后端、可离线、可复现。

## 一、本项目的定位：从后果中学习

许多学生难以直观体会一项政策为何「知易行难」——纸面设计良好的政策，落到执行层面却可能大幅走样。抽象的说理很难落地，可观察的后果可以。政策模拟把这种落差变成一段安全、可重复的经历：

- **建立代入感：** 以「政策委员会」的视角取代旁观者，让学生为自己的决策负责。
- **让后果可见：** 仪表盘精确显示每一项政策如何移动各指标，因果不再停留在讲义上。
- **提供即时且可解释的反馈：** 决策轨迹回放「选择 → 效果 → 为何如此」，因果不仅为真，而且被看见。
- **以复盘收尾：** 期末档位说明本周期走到了哪种结局、牺牲了什么、谁被影响、本可如何取舍。
- **跨主题可复用：** 引擎是通用的；新增课程政策只需追加独立的 JSON 数据包。

为 **PUA6027 科技、创新与政策** 而写，亦可用于其他科技政策类课程。

> **本课程的玩法细则另见教学指引。** 本仓库专注系统本身：如何运行、机制如何运作、如何扩展政策包。

## 三、设计哲学：Matland 双轨推演

这个项目要回答的设计问题是：**当学生目睹「好政策未必落地」时，会发生什么？**

单一的「意图计分板」有一个隐藏缺陷。学生很快学会最优策略——永远选最稳妥的选项——从而收集到「理想结局」。但这恰恰不是政策课程要教的：真实世界里，执行取决於标准的清晰度与利益的协调，再好的设计也会在执行中打折。

因此，每一条政策同时携带两类信息：

- **意图效果**（设计者期望它带来的影响）；
- **执行系数**（由 Matland 模糊—冲突二维模型决定，低模糊低冲突为行政性执行、系数 1.0，高模糊高冲突为象征性执行、系数 0.2）。

实际落到指标上的，是「意图 × 系数」。学生由此亲眼看见：意图隐私 +3 的政策，因高模糊高冲突，实际只 +1，甚至 +0。这正是本课程「知易行难」的核心理念，被做成可操作的机制。

| 设计决策 | 理由 |
|---|---|
| 原生 JavaScript（无框架） | 教学透明，学生可阅读并修改引擎，无需框架负担 |
| 引擎 / 数据分离 | 通用引擎 + 独立 JSON 政策包 → 加新政策无需改动代码 |
| 确定性 effects（无随机数） | 教育因果必须可复现、可解释——无掷骰、无运气 |
| 纯静态站点 | 满足硬性要求：随处部署、零运维、中国可访问（无境外服务依赖） |
| Matland 模糊—冲突模型 | 把「意图 ≠ 执行」做成可玩机制，而非抽象概念 |
| 指标仪表盘 + 决策轨迹 | 让因果被「看见」，且便于评分与复盘 |
| localStorage 持久化 | 刷新不丢失，支持跨周期累积与小组评分 |

## 四、如何运行

- **本地（无需服务器）：** 在任意现代浏览器中双击 `index.html`。
- **本地（带服务器）：** `python3 -m http.server 8000`，然后打开 `http://localhost:8000/`。
- **GitHub Pages（自行部署）：** 推送本仓库，进入 **Settings → Pages → Deploy from a branch**（选择分支与 `/ (root)`）。地址为 `https://<你的用户名>.github.io/PolicyLab/`。
- **重置：** 游戏内「重置课程」按钮可清空全部决策轨迹。

桌面与移动端均支持响应式布局。
