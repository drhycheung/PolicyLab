# 政策实验室 · PolicyLab

一门贯穿全课程的政策模拟系统——学生以政策委员会身份，面对随机抽中的政策难题，在固定层面下逐点决策；每作出一步选择，系统即时说明这一决策引发了什么改变，并在结尾给出详细复盘。执行结果由 Matland 模糊—冲突模型推演，可导出 Markdown / JSON / Word 报告。

**▶ 在线试玩：<https://drhycheung.github.io/PolicyLab/>**（启用 GitHub Pages 后生效）

</div>

---

**课程归属：** PUA6027 科技与创新政策（香港教育大学）。亦可作为其他科技政策类课程的政策模拟练习。课堂组织方式见 [教学指引](docs/teaching-guide.md)。

学生接手一个政策难题场景，以某一层面（宏观 / 中观 / 微观）的政策主体身份，依次面对数个决策点，就「怎么推行、怎么规定」作出选择。系统依据政策的「模糊度 × 冲突度」推演出执行结果，落点于 Matland 模糊—冲突模型的某一象限，并持续追踪十一項社会发展指标。全程纯前端、无构建、无后端、可离线、可复现。

文件：`index.html`、`css/style.css`、`js/engine.js`、`js/dashboard.js`、`js/app.js`、`js/docx.js`、`data/scenarios.js`；配套文档见 [教学指引](docs/teaching-guide.md)、[Vibe-coding 指南](docs/vibe-coding-guide.md)、[示例复盘报告](examples/示例报告-网约车算法-象征性执行.md)。无构建步骤、无后端、无 API 密钥；浏览器直接打开或部署至 GitHub Pages 即生效。

## 一、本项目的定位：从后果中学习

许多学生难以直观体会一项政策为何「知易行难」——纸面设计良好的政策，落到执行层面却可能大幅走样。抽象的说理很难落地，可观察的后果可以。政策模拟把这种落差变成一段安全、可重复的经历：

- **建立代入感：** 以「政策委员会」的视角取代旁观者，让学生为自己的决策负责。
- **让后果可见：** 每作出一步选择，系统即时给出「后果说明」——展示这一决策对指标的设计意图与实际落地（经本步 Matland 系数打折后），以及模糊度/冲突度与当前整体执行性格。
- **提供即时且可解释的反馈：** 决策轨迹回放「选择 → 模糊度/冲突度 → 为何如此」，因果不仅为真，而且被看见。
- **以详细复盘收尾：** 结尾给出完整复盘——决策轨迹、社会发展指标总账（开局→终局、由哪些决策点推动）、以及 Matland 归因，说明本局走到了哪一象限、为何如此。
- **可导出证据：** 一键导出 Markdown / JSON / Word（.docx）复盘报告，作为作业或课堂讨论素材。
- **跨主题可复用：** 引擎是通用的；新增课程场景只需追加独立的 JSON 数据包。

## 二、为课堂而设计

为 **PUA6027 科技与创新政策** 而写，亦可用于其他科技政策类课程。

> **本课程的玩法细则另见 [教学指引](docs/teaching-guide.md)。** 本仓库专注系统本身：如何运行、机制如何运作、如何扩展场景包。配套另含 [Vibe-coding 指南](docs/vibe-coding-guide.md)（如何以 AI 编码工具复现本系统）与一份 [示例复盘报告](examples/示例报告-网约车算法-象征性执行.md)。

当前为**垂直切片原型**：含 3 个通用政策难题场景，每局固定一个政策层面，每局 3 个决策点，用于验证核心机制，后续可扩展场景数量与决策步数。

## 三、设计哲学：情境驱动 + Matland 双轨推演

这个项目要回答的设计问题是：**当学生目睹「好政策未必落地」时，会发生什么？**

整体的玩法骨架参照《一念之差（Choices）》的「情境驱动」结构，但落点换成本课程的核心模型：

| 《一念之差》 | 政策实验室（PolicyLab） |
|---|---|
| 每次开局随机抽一个创业场景 | 每次开局随机抽一个**政策难题场景 × 政策层面**组合 |
| 每一步决定怎么做（分支选项） | 每一步决定**政策怎么推行 / 怎么规定** |
| 最终得出多种结局之一 | 最终落到 **Matland 模糊—冲突四象限**之一 |

单一的「意图计分板」有一个隐藏缺陷。学生很快学会最优策略——永远选最稳妥的选项——从而收集到「理想结局」。但这恰恰不是政策课程要教的：真实世界里，执行取决於标准的清晰度与利益的协调，再好的设计也会在执行中打折。

因此，每个决策点同时携带两类信息：

- **意图效果**（设计者期望它带来的影响，用于政策影响简报）；
- **模糊度 / 冲突度增量**（由本局固定层面的基线叠加，最终决定 Matland 落点）。

实际落到指标上的执行效果，是「意图 × 执行系数」。学生由此亲眼看见：意图良好的政策，因高模糊高冲突，实际几乎不落地——这正是本课程「知易行难」的核心理念，被做成可操作的机制。

| 设计决策 | 理由 |
|---|---|
| 原生 JavaScript（无框架） | 教学透明，学生可阅读并修改引擎，无需框架负担 |
| 引擎 / 数据分离 | 通用引擎 + 独立 JSON 场景包 → 加新场景无需改动代码 |
| 每局固定一个层面，不同局各有不同层面 | 呼应混合政策周期理论（宏观 / 中观 / 微观），让层面本身成为可比较的变量 |
| 确定性 effects（无随机数） | 教育因果必须可复现、可解释——仅「抽场景/层面」用随机，核心逻辑不放随机数 |
| 纯静态站点 | 满足硬性要求：随处部署、零运维、中国可访问（无境外服务依赖） |
| Matland 模糊—冲突模型 | 把「意图 ≠ 执行」做成可玩机制，而非抽象概念 |
| 指标简报 + 决策轨迹 + 指标总账 | 让因果被「看见」，且便于评分与复盘 |
| 每步「后果说明」+ 结尾详细复盘 | 贴近《一念之差》的反馈与复盘节奏，把「知易行难」做成可感知的经历 |
| 零依赖 Word 导出 | 手写 ZIP + OOXML 生成 .docx，离线可用、中国可访问、无第三方库 |
| localStorage 持久化 | 刷新不丢失，支持跨决策点累积与小组评分 |

## 四、如何运行

- **本地（无需服务器）：** 在任意现代浏览器中双击 `index.html`。
- **本地（带服务器）：** `python3 -m http.server 8000`，然后打开 `http://localhost:8000/`。
- **GitHub Pages（自行部署）：** 推送本仓库，进入 **Settings → Pages → Deploy from a branch**（选择分支与 `/ (root)`）。地址为 `https://<你的用户名>.github.io/PolicyLab/`。
- **重置 / 换局：** 游戏内「换一个场景」按钮可重新随机抽取「场景 × 层面」组合；localStorage 存档会在刷新后继续。

桌面与移动端均支持响应式布局。
